## Decision log
**DEC-1 — Contribute on top of the PR, never rewrite it.** New commits on
`bugfix/linux-port-hardening` based on `ealtun21:feature/linux-port`
(`c5b39b8`); the author's 17 commits are untouched. Account L0ic4 cannot push
to either repo, so changes go through a fork and a PR into the author's branch.

**DEC-2 — Tests use CTest + plain executables**, matching the existing
`dsp_selftest` style; no new test framework dependency. Live-graph tests are
labelled `pw-live` and exit 77 (skip) without a session.

**DEC-3 — Registry reads stay on the RT thread (mitigated, not removed).** The
shared DSP reads bypass/tuned-track state through the registry layer on every
block (upstream design; on Windows it is the real registry). Changing that is
an engine redesign. On Linux the lookups are now allocation-free and file I/O
happens outside the lock; the RT thread still takes a short mutex.

**DEC-4 — GUI/RT data races in the DSP engine: open, needs maintainer input.**
TSan reports 69 races when the message thread calls `setEqBandBoostCut` /
`powerOn` while the RT thread processes (`comSftwrWriteParam`,
`sosSetSection`, `dspsPlayInit`). The same calling pattern exists on
Windows. Candidate fix: a mutex in the `DfxDsp` facade taken by setters, with
`processAudio` using `try_lock` and passing the block through unprocessed (or
repeating the previous state) on contention. That changes shared code and
audible behaviour, so it is not done without agreement.

**DEC-5 — `lc_headers` generated by CMake in the build tree**, preferring the
DSP's own header copies over `audiopassthru/include` duplicates.

**DEC-6 — Default sink: trust `default.configured.audio.sink`.** While
WirePlumber switches to FxSound it briefly publishes another sink as
`default.audio.sink`; that key is only used when nothing is configured.

**DEC-7 — The FxSound sink monitor follows the sink volume
(`monitor.channel-volumes=true`).** Volume keys change the default sink, which
is "FxSound"; with the flag off the processor captured pre-volume audio and the
keys did nothing. The volume now applies before the DSP (as in EasyEffects), so
effects see a quieter signal at low volume.
